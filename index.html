QoreLab · Tekmyster Industries, LLC

Controlled by design

A framework built around evidence.

Modular scenarios

Locally installed test packages expose bounded options through CLI and client workflows, with matching receiver logic.

Independent accounting

Compare sender attempts with receiver-observed bytes, offsets and hashes. Keep complete, partial and unknown outcomes distinct.

Operator workflows

Client-initiated queues, approved canary hashing, DNS-only bootstrap, and separate HTTPS command and bulk-file channels.

The measurement path

ClientFinite scenario and budget→EnvironmentResolver and security tools→ReceiverIndependent arrival evidence

Delivery, resolution, collector visibility, detection, reported blocking and actual containment are separate outcomes. Missing telemetry stays unknown.

Transport options

Exercise different paths.

Development adapters include DNS over UDP/TCP, DoT, DoH, DoQ, HTTP/3, ODoH and DNSCrypt over TCP/UDP. HTTPS command and bulk-file workflows are separate. Normal NTP controls and experimental synthetic NTP scenarios have their own bounded scope. Availability depends on the platform and adapter dependencies.

Scenario catalog

Techniques with explicit measurement limits.

These are controlled workloads and observations. They do not establish comprehensive adversary emulation or vendor protection efficacy.

ScenarioWhat it measures
CNAME aliases — chain / unresolved target (TDSTS / RFC1034)alias-answer-pathFollow up to8 owned-session CNAME hops to a declared IPv4/IPv6 answer or synthetic NXDOMAIN. Observe alias/address rewriting without contacting returned addresses. Does not claim cache poisoning, real takeover or security enforcement.
DNS answer rotation — rebinding/fast-flux fixtureanswer-rotationAlternate configured A or AAAA answers for one owned test name, with TTL0. DNS queries only: the client never connects to the returned addresses. This is a controlled answer-behavior fixture, not an SSRF exploit.
Benign controls — long hostnamesbenign-long-hostnamesSend bounded long, word-like hostnames as a benign comparison corpus. Report observed DNS outcomes; false-positive classification requires independent product events.
DNS cache and retries — repeated names (TDSTS / RFC1035)cache-retry-observationCompare repeated names with unique names and authoritative arrival counts. The controlled receiver supplies the selected TTL. Client attempts and actual upstream delivery remain separate measurements.
DNS tunneling — Base32 synthetic transfercontrolled-transferMeasure independent delivery of synthetic bytes through the selected resolver. Uses offset-identified base32 query labels; complete and partial delivery remain distinct from security actions.
DNS query labels — custom ASCII (TDSTS / RFC 1035)custom-query-labelSend a small, bounded series of operator-entered ASCII labels, including punctuation, under the configured test zone. Captures raw and normalized authoritative observations. This is a query-pattern test, not verified file delivery or proof of detection.
Controlled DNS error and recovery observationdegraded-recovery-observationObserve bounded normal/error/normal response phases on distinct session-owned names. Synthetic response fixture only; no infrastructure outage, service restart or failover is induced or proved.
DGA-like labels — generated names (TDSTS / T1568.002)dga-like-namesGenerate a bounded reproducible corpus of high-variation labels inside the configured session zone. This evaluates visibility and classification; it does not recreate a malware DGA or register domains.
DNS command channel - fixed status / echodns-command-demoReceive a bounded status or echo command in DNS TXT answers and return a matching result digest in DNS questions. Fixed harmless operations only; no arbitrary execution or remote administration. Management coordinates the session separately.
DNSSEC — trusted owned-zone probes (TDSTS / RFC4035)dnssec-owned-zoneProbe separately provisioned signed, bogus and unsigned owned-zone names with DO/CD. Verify direct RRset signatures against a trusted local DNSKEY. Does not construct a root DS chain or authenticate unsigned status; coordinator arrivals indicate misrouting.
DNSSEC signatures — valid, invalid, unsigned (TDSTS / RFC4035)dnssec-signature-fixtureSix bounded DO/CD probes against a self-signed lab island, with client-side signature checks. Requires the dnssec extra on both ends. A key learned through the same DNS path is unauthenticated. This fixture does not provision a parent DS chain or establish resolver enforcement; use a separately trusted anchor and provisioned signed zone for that qualification.
DNS data transfer — experimental EDNS option (TDSTS / RFC 6891)edns-option-transferMeasure independent delivery of finite synthetic bytes in local/experimental EDNS option65001. Resolvers may strip unknown options; missing bytes alone are not enforcement.
DNS tunneling — encoded subdomainsencoded-label-transferSend synthetic data in unique subdomain labels using Base32 or hexadecimal encoding. Independently verify received bytes. A, AAAA and TXT refer to query types; this test does not carry file data in TXT responses. Encoding is not encryption. For DoT/DoH, select the resolver's actual TLS/HTTPS port and trusted certificate identity.
DNS file transfer — operator filesfile-transferTransfer selected local files through DNS query names or a local/experimental EDNS option in 64-KiB segments. The receiver reconstructs only DNS-observed bytes and independently verifies complete-file SHA-256. Select one ISO or multiple small files. Original TDSTS workload; technique reference MITRE ATT&CK T1048, not a copied exploit.
DNS policy — allowed / blocked names (TDSTS / DNS-006,007)policy-response-observationCompare configured-policy response codes for two explicit labels in the owned receiver zone. The authoritative fixture answers both normally; the tool changes no product policy. Matching codes do not establish detection or containment.
DNS query patterns — beacon / unique labelsquery-patternSend a bounded sequence of synthetic unique or repetitive labels. Measures receiver observations and DNS responses, without assigning a file-transfer byte count or claiming behavioral detection.
DNS rate steps — bounded unique queries (TDSTS / RFC 8198)rate-step-observationCompare finite synchronous query stages at operator-selected rates within the global limits. Reports separate client attempts and independent receiver arrivals; no overload threshold, protection or infrastructure-recovery result is inferred.
DNS record observations — A / AAAA / NS / MX / SOA / CAA (TDSTS / RFC 1035)record-observationObserve finite DNS record queries in the random owned session with synthetic authoritative replies. A/AAAA compare the answer with a known documentation address. Missing or changed answers do not alone prove poisoning, hijacking or containment. No third-party enumeration or zone transfer.
Provisioned DNS baseline before and after loadresolution-preservationQuery1–8 separately provisioned relative owned-zone A/AAAA names before and after0–64 synthetic session-owned questions. Compare complete exact-owner address sets; retain missing/error/unattempted observations. Coordinator baseline arrivals mean misrouting. Does not certify general DNS availability or attribute changes to security enforcement.
DNS response sizes — bounded ratio fixture (TDSTS / RFC 5358)response-size-observationMeasure paired DNS request/response message sizes with finite benign TXT replies in the owned session. The fixture respects a bounded advertised response size. No source spoofing, victim reflection, flood or vulnerability conclusion.
Subdomain proliferation with preserved baselinesubdomain-proliferation-observationObserve1–64 new session-owned child names between two known baseline address checks. Synthetic DNS fixture only; no domain compromise or malicious hosting is performed.
OS DNS path — synthetic QNAME transfersystem-query-transferPerform bounded A lookups through the native Windows/Linux name service, preserving its routing and caches. Receiver verifies only actual DNS arrivals. Counters describe logical API calls; wire queries, response codes and selected resolver are unobserved.
DNS TXT — response data transfer (TDSTS / T1071.004)txt-response-transferReceive a server-generated synthetic fixture through TXT answers. Source bytes are generated only on the receiver; control carries size and hashes. Client verifies each source offset and the complete hash.
